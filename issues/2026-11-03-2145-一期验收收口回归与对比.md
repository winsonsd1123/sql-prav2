## 第二件：演练场漏桩根治

### 核对方法（实证，不靠读代码推断）

临时在 `presetLoginState` 里挂了一个 context 级兜底路由作为探针。Playwright 中 page 级路由优先于 context 级，所以只有**没被任何 spec 桩接住**的占位主机请求才会落到探针上；探针记下「spec / 用例 / 请求地址」后调用 `fallback()` 原样放行，不改变行为。用它跑全量拿到泄漏清单，补桩后再跑一次确认**泄漏 0 条**，之后移除探针（不入库）。

补桩前的泄漏清单（数值为请求次数）：

| spec | 漏桩的表 |
|---|---|
| playground-smoke | practice_progress 44、domain_pack_asset 42、pack_exposure 42、user_roles 42 |
| no-paste | 四表各 10-11 |
| worker-execution-guard | 四表各 8 |
| draft-persistence | practice_progress 7，其余三表各 5 |
| progress-cloud-sync | domain_pack_asset / pack_exposure / user_roles 各 8 |
| permission-exemption | domain_pack_asset / pack_exposure / practice_progress 各 2 |
| admin-console | domain_pack_asset / pack_exposure 各 2（即「无权限点直访 /admin」一例，flake 表原 214→217） |
| login | 四表各 1（「已预置登录态」一例） |
| cloud-domain-pack / practice-config / pack-exposure / generate-page / refine | 只漏 practice_progress，各 2-3 |

结论：漏的不只是 `practice_progress`。演练场加载时还会拉 `domain_pack_asset`、`pack_exposure`、`user_roles`（`role_permissions` 只在有角色时才查，空角色不会触发）。这些请求要么挂起，要么在全量并发下被断开、报 `ERR_CONNECTION_CLOSED`，与 #97 trace 的结论一致。

### 修法

1. **`e2e/helpers.ts` 新增 `stubPlaygroundBackend(page)`**：五张表（`practice_progress`、`domain_pack_asset`、`domain_pack_version_history`、`pack_exposure`、`user_roles`）一律回空行集。
   - 进度表**无状态**：读返回空，写直接丢弃。第一版复用有状态的 `createCloudProgressStub`，结果 playground-smoke「已通过题再次验证…」变红：用例前段写入的「题 0 已通过」在 `seedProgress` 刷新后又被云端恢复合并回来，打破了「本地进度是唯一真相」的用例前提。补桩前请求挂起，云同步实际处于失效状态；无状态桩保留了这层语义，而且结果确定
   - 必须在用例级桩**之前**挂（beforeEach）。Playwright 后注册的路由优先，用例自己的权限 mock、资产夹具等因此能覆盖它
2. **纯演练场 spec 在 beforeEach 挂整页桩**：playground-smoke、no-paste、draft-persistence、worker-execution-guard、permission-exemption
3. **progress-cloud-sync**：每个用例（含跨上下文的 pageB）先挂整页桩，再挂自己的有状态 `createCloudProgressStub`，由后者覆盖进度表；「断网兜底」的 500 故障层仍然最后注册
4. **admin-console**：「已登录」describe 的 beforeEach 把 `createCloudProgressStub` 换成整页桩；`mockAdminPageApis` 里与之重复的三张表空桩一并删掉
5. **login**：「已预置登录态」一例挂整页桩
6. **后台类 spec 中途进学生端的**（cloud-domain-pack、pack-exposure 挂 beforeEach；practice-config 挂在其 `mockStudentSide`；generate-page、refine 挂在进学生端前）：按票面**只补 `createCloudProgressStub`**。这些用例在进学生端前已经桩了带夹具数据的资产表，如果再挂整页桩，后注册的空集桩会把夹具覆盖掉
7. **`docs/e2e-conventions.md`**：打桩节新增一条整页桩用法；flake 表四行的根因列改为「演练场漏桩，已补桩根治（#98）」，并更新行号。交接文档列了三条，`practice-config:118→119` 症状相同、探针也证实它漏了 practice_progress，所以一并更新。按票面口径，这几行是否整行退役由验收方定

1. **toast 错误态观感与若依不同**（`06-toast.png`）：本项目是白底、红色图标、深色字；若依 `el-message--error` 是浅红底（#fef0f0）、红字、红边。#96 只收口了位置和时长，配色是否对齐若依留给验收拍板
