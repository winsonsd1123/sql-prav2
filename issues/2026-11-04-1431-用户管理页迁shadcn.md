## 上下文

二期第三批：用户管理页 `src/components/admin-users-list.tsx`（表格 + 搜索 + 分页 + 行内角色编辑 + 禁用启用）整体迁 shadcn——按钮迁 Button、表格迁 Table、卡片迁 Card；票面硬性要求评估是否引入 TanStack Table。搜索、分页边界、行内编辑与现状逐一等价，testid 不变。沿用 #99/#100 拍板：`输入框` 不动（#102）、字体/动画类（`标题`/`呼吸`）不动、`ui/` 现有件只消费不改、globals.css 不碰。

## TanStack Table 评估：不引入

票面要求「评估结论与理由记入 PR 描述」；二期走多票流水线（验收即合、无 PR），按交接文档落点偏差说明，结论记入本节，验收留痕时同步写入 issue #101 评论。

**结论：不引入 TanStack Table，用 shadcn Table 直接渲染。**

理由：

1. **它擅长的事这页都不在前端做**：TanStack 的价值在客户端的分页、排序、筛选、列显隐等状态和行模型管道。本页是**服务端分页 + 服务端搜索**——`GET /api/admin/users?q=&page=` 返回 `{users,total,page,pageSize}`，前端只持当前页；列头没有排序交互，也没有客户端筛选。真要接 TanStack 也只能开 `manualPagination` / `manualFiltering`，状态仍由组件自己的 `search` / `page` 驱动，TanStack 只剩把 `users` 数组原样转成行。
2. **复杂度在行内交互，TanStack 管不到**：难点是角色编辑展开/收起、自保护锁定、禁用启用防重入，这些要么是行外组件状态（`editingUserId`/`saving`/`banSavingUserId`），要么写在单元格渲染里。换成 `columnDef.cell` 只是把同样的 JSX 挪进列定义，再靠 `table.options.meta` 或闭包把状态传进去，读起来更绕。
3. **分页边界判定只有两行**：`totalPages = max(1, ceil(total / pageSize))`，配合 `page <= 1` / `page >= totalPages`，等价性已由 e2e（pageSize=2 驱动）覆盖。用 `getCanPreviousPage` 替换不会更简单，反而要同步 `pageCount`。
4. **成本**：新增运行时依赖 `@tanstack/react-table`（全库目前没有）、一层列定义抽象，以及与本页一致性无关的学习和维护成本——不符合 YAGNI。
5. **何时重新评估**：出现客户端排序、多列筛选、列显隐/列宽调整、行多选批量操作，或同类表格出现 3 个以上需要共享表格状态时，再引入；届时可以只在那张表局部引入，不影响本页。

## 观感变化——「突然生效」的旧设计意图：本页 0 处

逐处核对：迁移前被 unlayered 中文类压着的 utilities，需与 `.卡片`（background/border/border-radius/box-shadow）或 `.次按钮`（background/color/border/border-radius）同属性才会被压制。

| 元素 | 原 className 中的 utilities | 与中文类冲突？ |
|---|---|---|
| 外层卡片 | `p-4` | 否（`.卡片` 不管内距）——Card 默认 `rounded-lg` = 4px、`border-border`、`bg-card`、卡片阴影，与 `.卡片` 同值 |
| 搜索 / 分页按钮 | `shrink-0 px-3 py-1.5 text-xs` | 否 |
| 保存 / 取消 / 编辑 | `px-2.5`/`px-2` `py-1`/`py-0.5` `text-[11px]` | 否 |
| 禁用启用 | `px-2 py-0.5 text-[11px]` + 锁定时 `cursor-not-allowed opacity-60` | 否（`.次按钮` 不管 opacity；`cursor` 原本就生效） |

结论：本页没有「写了却不生效」的类，迁后不会冒出旧设计。

## 发现待办（范围外，未修）

1. **Button 基类 `disabled:pointer-events-none` 与「禁用 + title 解释」模式冲突**：本页两处用使用点反覆盖（拍板第 2 条），其他页面若出现同类「禁用按钮带原因提示」也会静默丢提示，e2e 断言属性测不出来。建议 #102 根修 ghost 变体时一并考虑：基类改用 `disabled:cursor-not-allowed`，悬停样式改 `not-disabled:hover:*`
2. **`横滑` 与 Table 容器的组合**：Table 自带滚动容器，外层的 `横滑` 无法直接作用。本页用任意变体下推；如果后续有更多横滑表格，可以考虑让 `ui/table.tsx` 的容器接受 className（改 `ui/` 归 #102）
