# LLM provider 与域包生成 API（#59）

## 上下文

spec #53 目标②、ADR-0008：教师端「描述 → LLM 起草域包 JSON → 闸门 → 确认发布」。
前置：#56 契约与闸门、#57 云端存储与 upsertDomainPackAsset、#55 双权限点鉴权模式。
基点：feature/domain-pack-system @ c7632c9（含合并票 #57）。

## 计划

- 薄 provider 抽象（LlmProvider 接口 + DeepSeek 实现，key 只在服务端 env）
- 提示词组装器（嵌入 #56 契约全文与占位符语法，满足 DeepSeek json_object 前提）
- 生成/发布编排服务（鉴权双权限点 → LLM → 闸门 → 草稿+报告 / 发布重过闸门走 #57 写入）
- 两个 admin route（generate：maxDuration=300；publish）
- provider 全程 mock 单测；真实 DeepSeek 冒烟（有 key 才跑）；路由协议边界 e2e

## 执行记录

- 模型 id 查证（2026-11-01，api-docs.deepseek.com/zh-cn）：Flash 档现标识 `deepseek-flash`
  （已升级 V4.1-Flash-1017，调用方式不变）；base url `https://api.deepseek.com`；
  支持 `response_format: {"type":"json_object"}`，前提 prompt 含「json」字样并给格式示例，
  偶发空回复（content 置空但 finish_reason=stop）——provider 按可重试错误上抛。
- 新增文件：src/server/llm-provider.ts、src/server/domain-pack-prompt.ts、
  src/server/domain-pack-generation-service.ts、

  e2e/domain-pack-generation.spec.ts；.env.example 增 DEEPSEEK_API_KEY/BASE_URL/MODEL。
- 发布「版本 1」口径：domain_pack_asset 无版本列（#62 落版本历史），
  首次 upsert 即版本 1，pack_id 基础名即当前最新版本。
