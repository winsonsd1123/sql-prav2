## 施工前拍板（用户确认）

1. **`卡片` 也清零**：新建 `ui/card.tsx`，只提供 Card 一个组件，替换范围内全部 `卡片`
2. **`输入框`（含 `.错误`）本票不动**：票面只写按钮与表格，交 #102 定夺（见「发现待办」2）
3. **`标题`/`入场`/`落章`/`呼吸`/`横滑` 不算控件类**：字体与动画类，不动
4. **套按钮类的 `<Link>` 改为 `<Button asChild>`**：共 4 处，testid 挂在 Link 上不变
5. **改 `button.tsx` 的 outline 变体**：原变体的 `hover:bg-muted` / `aria-expanded:bg-muted` 撞上项目的 `muted` 语义（Tailwind 颜色 `muted` = `--色-次文` #606266，见 `globals.css` 第 93-95 行注释），悬停会变成深灰底配深字，「表结构」按钮（默认 `aria-expanded=true`）会常驻深灰。改为若依次按钮：白底、一阶灰边、次文字色，悬停与 `aria-expanded` 时主色浅底/浅边/主色字。改之前全库没有 outline 的使用者

## 改动

- `ui/card.tsx`：`rounded-lg border border-border bg-card shadow-[var(--阴影-卡片)]`，与 `.卡片` 的 token 逐项对应（面板底、三阶边框、`--radius`、卡片投影）。不带内距与布局，由使用点决定；支持 `asChild`，用于 form / aside / nav / section / p / pre 等语义元素

## 与 before 的可见差异（请验收方确认）

1. **卡片左色条与错误结果底色开始生效**：`.卡片` 定义在 `globals.css` 里，不在任何 `@layer` 中，优先级高于 Tailwind utilities 层，于是它的 `border: 1px solid` 一直压着代码里写的 `border-l-4 border-l-{pass|warn|fail}`，`background` 也压着「错误」结果卡上的 `bg-deep`。换成 Card 后这些类终于生效：通过/不通过/拦截/禁粘横幅/通过反馈条出现 4px 语义色左边条，SQL 错误卡变成浅灰底（见 `after/playground-diff.png`、`after/session-summary.png` 背景）。这符合代码里写的设计意图，但属于观感变化。如果要保持旧观感，删掉这几处的 `border-l-4 border-l-*` 与 `bg-deep` 即可（6 处，几行改动）
2. **「表结构」按钮展开态**：从淡描边环（`ring-1 ring-ink/15`）变成主色浅底/主色字，由 outline 变体的 `aria-expanded` 态统一表达（拍板 5）
3. **按钮高度统一为 shadcn 尺寸**：原写法 `py-*` + 行高 + 2px 边框，比对应 size 高 2px（顶栏 30→28、提示/验证/提交 38→36）。窄屏长图短 8px 就是这些累加出来的。题号条按钮各宽 2px（Button 自带 1px 透明边框），窄屏横滑条里 `#06` 露出的部分少了一点，滚动可见
4. **禁用态次按钮字色略深**：原 `.次按钮:disabled` 把字色换成占位色，现在是次文色乘 `opacity-40`

## 发现待办（范围外，未修）

1. **ghost 变体也有 `hover:bg-muted` 冲突**：Dialog 右上角关闭按钮（`ui/dialog.tsx`，`variant="ghost"`）悬停时是深灰底。本票按约束没动 ghost；本票里两处 ghost 使用点用 className 覆盖解决。建议 #100 或 #102 一并把 ghost 改成 `hover:bg-secondary`（= 行悬停色），或者统一处理 `muted` 命名冲突
2. **`输入框` 还没有 shadcn 对应物**：认证四页共 7 处（含 `.错误` 态）。#102 要求「全库无残留引用」，需要有一票新建 `ui/input.tsx`（错误态用 `aria-invalid`）并完成迁移，admin 端也有使用
3. **未分层的中文类压制 utilities**（即差异 1 的根因）：其余仍在用 `.卡片` 的页面（admin 端）大概率有同类「写了不生效」的类，#100/#101 迁 Card 时会同样冒出来，建议在那两票的施工说明里预先写明
