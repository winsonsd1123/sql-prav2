# 四处 admin 内联 notice → 全局 toast（#96）

日期：2026-11-03 · 票：#96（父 spec #90，ADR 0011）· 分支：feature/ruoyi-ui-96（基点 1ef47d1 = main，#95 merge）· 施工方：Cursor

## 上下文

ADR 0011 点名的第二处真实缺陷：四个 admin 管理器各自内联重复实现 notice 段落，反馈出现即把表单顶开。本票收口为全局 toast，只换反馈形态，不碰写操作时序。

## 选型

shadcn 官方文档已标注 `toast` 组件弃用、改用 `sonner`（Radix 基座项目即用 Sonner），故 `pnpm exec shadcn add sonner` 取 `src/components/ui/sonner.tsx`，新增依赖 `sonner@2.0.8`。

对 CLI 产物的必要改动（与 #95「原样保留」口径不同，原因逐条）：

- **去 `next-themes`**：CLI 产物用 `useTheme()`，无 Provider 时回落 `"system"`——会跟随系统暗色，违反 ADR 0011 单主题。故 `theme="light"` 写死，`next-themes` 依赖随之移除（未入 package.json）
- **语义色只落在图标**：success / error / warning / info 图标分别取 `text-pass` / `text-fail` / `text-warn` / `text-accent`（既有 token）；不开 `richColors`（Sonner 自带 hsl 色板 = 新色值）
- **字体继承**：Sonner 注入的 `[data-sonner-toaster]` 自带 `font-family`（非图层样式，压过 Tailwind 工具类），以内联 `fontFamily: inherit` 回到站点黑体
- 卡片底 / 字 / 边框 / 圆角沿用 CLI 产物的 `--popover` / `--popover-foreground` / `--border` / `--radius` 映射——即既有白卡、`#303133` 墨色、三阶边框、4px 圆角

挂载：`<Toaster position="top-center" />` 置于根 `layout.tsx`（官方推荐位）。**位置选 top-center 而非 top-right**：视觉自检发现 1280 宽下右上 toast 正压住白名单卡右上角的「放开 / 收紧」按钮（违反「不遮操作区」）；顶部居中与若依 Element `Message` 落点一致，四页该区为标题行 / 面板空白。

## 改动

1. **四处 notice 删除清单**（状态 + 写操作起点清空 + 条件渲染）：
   - `admin-whitelist-manager.tsx`：`notice` state、`toggleAllowAny` / `saveDomains` 起点 `setNotice(null)`、`data-testid="白名单提示"` 段落
   - `admin-knowledge-area-manager.tsx`：`notice` state、`runWrite` 起点 `setNotice(null)`、`role="status" data-testid="词表提示"` 段落
   - `admin-practice-config-manager.tsx`：`notice` state、`save` 起点与 `switchPack` 的 `setNotice(null)`、`role="status"` 段落
   - `admin-pack-exposure-manager.tsx`：`notice` state、`save` 起点 `setNotice(null)`、`role="status"` 段落
2. **反馈改道**：写操作成功 `toast.success(原文案)`；写操作失败（服务端文案经 `readErrorMessage` / `errors.join("；")` / `cause.message` 透传，网络异常落原兜底文案）`toast.error(原文案)`。文案逐字未改
3. **单槽语义**：每个管理器一个固定 toast `id`（与 testId 同名），新反馈原位替换旧反馈——对齐原 `notice` 单值槽「后一条覆盖前一条」，也避免连续操作堆叠同 testid 元素。演练配置 `switchPack` 原「切包清 notice」改为 `toast.dismiss(id)`，语义保真
4. **保留内联的错误**：加载失败（`refresh`）与「登录态已失效」仍走内联 `error`——前者是页面级状态（列表都没拉到，无内容可操作），后者在词表管理器里由 `requestApi` 读写共用、在其余三处与加载共用同一形态，属会话态而非某次写操作的反馈；成功路径原有的 `setError(null)` 一并保留
5. **busy 边界**：`if (busy) return` / `setBusy(true)` / `setSaving(true)` / `setSwitching(true)` 与各 `finally` 解锁一字未动；diff 中这些行无改动，只删去紧随其后的 `setNotice(null)`
6. **e2e**：见下「testid 处理」；新增 3 例——
   - `admin-whitelist.spec.ts`「成功 toast（#96）」：浮出（`data-type=success`）、反馈前后「白名单总开关」分区 boundingBox 不变（不顶开布局；基线取在入场动画落定后）、视口顶部居中、10s 内自动消失
   - `admin-whitelist.spec.ts`「失败 toast（#96）」：PUT 桩 400 → toast 透传服务端文案、`data-type=error`、保存按钮立即可用（finally 解锁）、草稿保留
   - `admin-knowledge-areas.spec.ts`「写操作失败（#96）」：PATCH 桩 400 → `runWrite` catch 路径透传文案、条目状态不变、按钮解锁
   - 两 spec 的 console 卫生对桩出的 `status of 400` 资源报错单独豁免（在 `afterEach` 里过滤，见「发现待办」1）

| 知识点词表 | `词表提示`（notice 与 error 共用） | toast 同挂 `词表提示`；内联 error 段落改名 `词表错误`（对齐 `白名单错误`，避免与 toast 同名并存；全库无断言引用 error 侧） | 原断言零改动 |

| 域包放出 | 无（同上） | toast 新挂 `放出提示` | `pack-exposure.spec.ts:118` 同理改 `getByTestId("放出提示")` |

## 发现待办（范围外，未修）

1. `domain-pack-refine.spec.ts:15` 与 `domain-pack-generate-page.spec.ts:21` 的 console 卫生写法 `collectConsoleProblems(page).filter(...)` 在 `beforeEach` 时就对空数组做了拷贝，此后页面的 console 报错推入的是原数组——**这两个 spec 的 console 卫生断言实际恒为空、形同虚设**。本票两 spec 改为在 `afterEach` 过滤；修那两处需同时确认它们恢复断言后仍绿，属另票
2. `pnpm-lock.yaml` 除 sonner 外有 3 个 `@babel/*` 传递依赖补丁位上浮（7.29.8/10/11 → 7.29.12）：在 main 上 `pnpm install` 无漂移，加入 sonner 触发 pnpm 重解析所致，不可单独剔除；全量测试在此 lockfile 下全绿
3. 失败反馈原先常驻（直到下次操作），现随 toast 4s 自动消失——票面要求的行为，记于此供验收知悉；长服务端文案（如演练配置 `errors` 多条拼接）在 4s 内可能读不完，若需要可单独给 `toast.error` 加长 `duration`
