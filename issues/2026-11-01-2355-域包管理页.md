# 域包管理页（#60）

日期：2026-11-01 · 票：#60（父 spec #53）· 分支：ticket/60-admin-domain-pack-page（基点 d209679 = 合并票 #61）

## 上下文

教师端域包全生命周期入口：LLM 起草 → 闸门报告 → 确认发布 → 列表/放出/配置统一收纳。
前置产物对接：#59 generate/publish 路由与编排服务、#56 GateReport、#57 cloudPackStore/domain_pack_asset、#58 内置 JSON 资产、#61 演练配置区块、#55 放出管理区块。

## 关键决策

1. **路由选择：演进 /admin/packs 而非新建 /admin/domain-packs**。#55/#61 已把放出管理与演练配置放在 /admin/packs，e2e 断言（pack-exposure.spec、practice-config.spec）也指向该路径；演进避免新增路由 + 旧页清理 + e2e 全量改址三重成本。侧栏入口「域包放出」更名「域包管理」（独立放出入口即告移除）。
2. **域包列表数据来源：复用 #57 加载层，不加管理端只读 API**。页面直接消费 cloudPackStore（RLS authenticated 可读，与学生端同源）+ builtinDomainPacks，经 mergePackRegistries 合并；管理页与学生端永不异视。放出状态列由列表区块自查 GET /api/admin/pack-exposure（空清单 = 默认全放，与放出管理同语义）。
3. **组件级单测形态**：仓库无 DOM 渲染测试设施（vitest 仅 *.test.ts、无 testing-library），沿用「纯函数抽离 + 薄组件」先例——视图模型与流程状态转移收口在两个纯函数模块（domain-pack-admin-view-model / domain-pack-generation-flow），18 条单测锁死口径；组件只做渲染编排，由 e2e 覆盖交互。
4. **LLM 打桩设计（e2e）**：Playwright 拦截不了服务端出站 fetch，但本页对 /api/admin/domain-packs/* 的 fetch 发生在浏览器内，page.route 即可打桩——**不引入任何服务端测试开关**（env flag / 注入 fake provider），生产路径零改动、测试态不可被生产触发。取舍：e2e 不再穿透真实路由编排（该边界已由 #59 的 domain-pack-generation.spec 直打路由覆盖 400/401/503）与真实闸门（#56 单测覆盖）。发布后学生端可见可练用 #57 的 domain_pack_asset 浏览器桩回放已发布资产行闭环。console 卫生对桩注入的 502/503 资源错误做显式过滤（注释写明理由）。
5. **发布后即时刷新**：发布成功回调 cloudPackStore.forceReload()（清就绪标记重拉），管理页列表与放出管理即时纳入新包——e2e 首跑暴露的真实缺口（不刷新则教师须手动重载页面才能放出/看到新包）。
6. **收纳**：AdminPackExposureManager（#55）props 来源从内置注册表换成合并资产清单（组件本身零改动，兑现其「换 props 来源」预留）；AdminPracticeConfigManager（#61）整块迁入（本就与页面无耦合）；两者既有 e2e 断言语义（放出过滤、配置改 7 题）不变，仅补管理页新增请求的离线桩。
