# 演练配置切包重拉竞态修复（#103）

日期：2026-11-04 · 票：#103（独立行为 bug，源自 #97 验收待办）· 分支：feature/103-switch-refetch-race（基点 a6517c1 = main）· 施工方：Cursor

## 上下文

`admin-practice-config-manager.tsx` 的 `refresh` 用 `useCallback(..., [selectedPackId])`，挂载 effect 依赖 `[refresh]`：每次切包 → `refresh` 重建 → effect 重跑 → 多余 GET，回包用服务端配置重置草稿。切包后若在回包前开始输入，输入被冲掉。切包所需数据（`entries` 全量包配置）已在内存，`switchPack` 本就在事件处理器里本地回填草稿，GET 只在挂载与保存成功后需要。

## 修复方向选择

选交接文档方向 3（切包纯本地化），落地形态为 **`refresh(keepPackId)` 参数化**：

- `refresh` 不再闭包读取 `selectedPackId`，改由调用方传入要保持的选中包；依赖数组变 `[]`，effect 只在挂载时执行
- 挂载：`refresh(null)` → `nextSelected = keepPackId ?? body.packs[0]?.packId ?? null`，首拉无选中取第一个包的回退逻辑原样保留
- 保存成功：`refresh(selectedPackId)`（`save` 本就依赖 `selectedPackId`，闭包值即当次保存的包），保存后重拉与选中保持不变
- 切包：`switchPack` 一字未改，纯本地回填

理由：

1. 对比方向 1（空依赖 + lint 豁免注释）：不需要豁免 `react-hooks/exhaustive-deps`，依赖数组诚实
2. 对比方向 2（ref 读取选中值）：不引入 ref 同步这层间接状态，数据流显式（谁调谁传），KISS
3. 改动面最小：组件内 4 处改动（签名、回退读参数、依赖数组、两处调用点），无新增状态/副作用

## 行为对照

| 场景 | 修复前 GET 次数 | 修复后 GET 次数 |
|---|---|---|
| 挂载首拉 | 2（首拉设选中 → `refresh` 重建 → 再拉一次） | 1 |
| 每次切包 | 1（多余，回包覆盖草稿） | 0 |
| 保存成功 | 1（save 内重拉）+ 选中未变不再追加 | 1 |

反证实测：旧组件 + 新 spec，挂载后 GET 计数为 2（新组件为 1）——挂载阶段的第二次 GET 同属本竞态链路（同一回包重置草稿），一并消除，非额外行为变化。

其余逐一不变：挂载首拉与加载态、首个包默认选中、保存后重拉与选中保持、切包本地回填与 toast 收起、`saving` busy 时序（`finally` 复位在重拉之后）、校验与按钮禁用、全部 testid。`globals.css`、`ui/` 零接触。

## 测试

- **新增** `e2e/practice-config.spec.ts`「切包后立即输入不被覆盖（票 #103）」：后注册路由计数 GET 并把首拉之后的 GET 延迟 300ms（放大覆盖窗口）；切包后不等任何请求立即填写总题数 9 / 档4 1，等过桩延迟后断言输入保留、切包未产生 GET；再保存断言 PUT 载荷为所选包与所填值，busy 复位（重拉落定）后断言全程只多保存后那 1 次 GET
  - 反证：换回 main 组件跑，红在「总题数期望 9、实际 10」——即竞态本身
- **改写** :157「域包下拉切换（票 #97）」：删除 `networkidle` 等待与 `waitForResponse` 绕行（含「避免填写被覆盖」注释），其余断言（草稿回填、档4 模板数、保存载荷、保存后选中保持）不动
  - 反证：旧组件下删绕行后的该用例超时，证明绕行确实是为竞态而设，修复后可删
