# 题库：域包模板体系（语义角色占位符 + 种子实例化）

题目必须随会话随机变化（防抄袭、每人题面不同），同时判题需要稳定的参考答案与判定元数据。二者通过**域包（domain pack）**调和：每个域包定义一个业务场景的库骨架（表与关系的语义角色）、数据生成规则和一组题目模板；模板以语义角色占位符（`{{table.X}}`/`{{col.T.C}}`/`{{param.X}}`）编写，永不引用具体表名列名；一次会话 = 随机选域包 + 种子驱动实例化（列名从每语义角色的候选池随机选定、参数随机、数据随机）。种子持久于 localStorage 并展示在 URL，同种子字节级复现同一套题。

## Considered Options

- **每题独立小库（LeetCode 模式）**：判题简单，但题目间无连续性，学生缺少"认识一个库再查询它"的真实感，被否决。
- **全局题库任意模板套任意库**：模板无法稳定引用语义，不可行。
- **运行时 LLM 生成题目**：防雷同收益与既有的四层随机（数据/表名列名/参数/注入边界值）高度重叠——抄来的 SQL 因列名不同会直接报 1054 错误，本身就是教学时刻；而它打破三个已确认决策（纯静态部署、种子确定性复现、模板自带参考答案）并引入费用、延迟与生成质量风险。LLM 改为离线辅助起草模板的工作流；"AI 错误讲解"列二期候选。
