# 域包：数据资产化与教师端 LLM 起草

域包从"编译进前端的 TS 字面量 + YAML 静态 import"改为 Supabase 里的 JSON 数据资产，使教师能在运行时扩充题库：教师在后台以自然语言（可附难度 SQL 样例）描述场景，由 LLM（DeepSeek，薄 provider 抽象，key 只存服务端 env）起草完整域包 JSON（库骨架 3-5 表 + 25-35 道模板 + 知识点清单 + 难度档位定义），经机器验证闸门（结构/生成/自判三类检查，复用全量回归测试的断言口径）与教师确认后发布。学生端演练仍是种子确定性纯函数，LLM 永不参与学生端题目生成（0002 的否决范围即"学生端运行时生成"）。内置两套域包迁移为同格式数据资产，packId 不变、同种子字节级复现同一套题为硬约束，消灭代码态/数据态双轨。

## Considered Options

- **双轨并存（内置包编译期 + LLM 包运行时）**：两套加载链路、两套心智模型，复现路径分叉，被否决。
- **LLM 产出 TS 代码动态执行**：等于不可审计的 eval，被否决。
- **异步任务式生成**：Vercel 函数 maxDuration=300s 容得下 1-3 分钟的同步生成，任务表+轮询是纯增量复杂度，被否决（YAGNI）；超时给重试入口，不静默降级。

## Consequences

- 域包注册表从模块级同步常量改为"内置同步 + 云端异步合并"的加载层，需处理异步就绪前的回退，首屏不得闪错域包。
- 知识点顺序表（原硬编码于 question-picking.ts 的七类）成为域包字段，各包自带清单与顺序。
- 难度 1-5 各档在域包上挂"名称 + 描述 + 代表 SQL 样例"的定义；演练配置（每次会话总题数 + 各档数量分布）为域包级配置，学生无限次开练均按当前配置生成。
- 域包放出（学生可演练清单 = 教师放出的域包子集）依赖本决策的资产化注册表；未配置时默认全部放出。
