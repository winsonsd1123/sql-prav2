# 防偷看：摩擦力设计而非访问控制

学生自主练习场景下，提示与参考答案若点击即看，不想思考的学生开局即可抄答案；SQL 也可从 AI 工具或同学处复制粘贴直接作答。本仓库选择**摩擦力（friction）设计**：提示与参考答案按"尝试"分级解锁（提示需 ≥1 次尝试；参考答案需累计 3 次不通过尝试、或已看提示后再试 1 次，且解锁前有确认框）；编辑器拦截粘贴与拖入（保留表名/列名补全兜底）；借助答案永久挂徽章并计入完成分档。学生**始终最终能看到答案**——门槛的价值在于把"先自己试"变成阻力最小的路径，而非剥夺参考权。通过后的题目全解锁（含参考答案），通过后查看不记"已借助答案"，那是对照学习而非借助。

## Considered Options

- **教师解锁码/账号体系（考试模式）**：绝对封禁答案，但演练场无账号体系、纯静态部署、面向自主练习而非监考——为少数考试场景引入身份基础设施，破坏"零后端"决策，被否决。
- **仅确认弹窗**：实现最简，但点击一次确认即过，摩擦力趋近于零，不改变"开局抄答案"的行为路径，被否决。
- **延时解锁（该题停留 N 分钟后才出现提示）**：惩罚的是思考快的学生，且对思考慢的学生是等待惩罚而非引导，与教学目标错位，被否决。
- **对抗技术型绕过（禁 DevTools、检测禁 JS）**：粘贴拦截可被 DevTools/禁 JS 绕过是已知且接受的边界——这是游乐场规则不是考场规则，规则宣示（拦截横幅）优于猫鼠游戏。
