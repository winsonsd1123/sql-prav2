# 域包：参与种子生成的内容不可变（版本化微调）

种子确定性复现意味着"同域包内容 + 同种子 = 同一套题"，而练习进度以 `(user_id, seed, pack_id)` 为键、题目以会话内 0 起题号索引关联、无任何版本校验——域包内容一旦在会话进行中被修改，学生的 `passedIndices`/`drafts`/`attemptCounts` 会静默错位到别的题目上。因此域包修改分两类：**不参与种子生成的**（难度档位定义、演练配置）即时生效、不产生版本；**参与种子生成的**（库骨架、名称池、题目模板、数据规则）每次修改产生新版本，packId 带版本后缀（如 `student-course-grade@v2`），进行中会话停留在进入时的版本直到换一套或重新进入，云端进度按旧键自动隔离，表结构与 RLS 零迁移。

## Considered Options

- **直接覆盖生效**：实现最简，但所有进行中会话的进度作废或错位，学生体验有损，被否决。
- **按 templateId 迁移进度**：题目序列由分区+洗牌派生，索引级错位无法可靠映射回模板，被否决。

## Consequences

- 域包需保留历史版本供旧会话加载；新会话只使用最新版本。
- packId 基础名永不更改（改名会使云端进度三元组键成为孤儿行）。
- 域包微调与新建共用同一闸门（机器验证 + 教师确认），微调是 LLM 辅助修改已有域包的常规入口。
- 知识点清单（knowledgeAreas）同样属于参与种子生成的内容，其变更归 B 类：知识点序参与抽题分区，改动会使同种子的题序漂移，旧会话进度同样会错位。
