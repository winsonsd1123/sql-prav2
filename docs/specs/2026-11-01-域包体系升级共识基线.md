# 域包体系升级——共识基线（2026-11-01）

状态：**已与需求方逐题确认**（23 项决策全部收口），作为 to-spec / to-tickets 的输入基线。
配套决策载体：GLOSSARY.md（术语）、ADR-0002（修订）、ADR-0008、ADR-0009。

## 总纲

一个 spec 覆盖三个目标，实施顺序 **① 参照完整性 → ③ 域包放出 → ② LLM 生成域包与难度配额**（①是契约地基，③独立且轻，②最重）。

## 目标①：参照完整性

- **数据层断言**：生成的数据必须满足——FK 值全部指向被引用表真实存在的行、PK 唯一、NOT NULL 列无 NULL；引用池剔除 NULL、表生成按依赖拓扑排序、空引用池显式报错。UNIQUE 视现状而定，CHECK 本轮不做。
- **DDL 层**：建表语句声明 `PRIMARY KEY` / `FOREIGN KEY` 子句，让库结构自带完整性语义。
- **学生端 UI**：列清单打徽章（主键、`FK → 表.列` 外键指向），不加 DDL 原文视图。

## 目标③：域包放出

- 学生端"可演练数据库列表" = 教师放出清单的过滤结果，交互与现有域包切换胶囊一致。
- 系统级清单（不按班级/学生组），由新权限点（域包管理）控制谁能改；**未配置时默认全部放出**（向后兼容）。
- 粒度 = 域包级（整个域包可见/不可见，不做表级拆分——半库状态会产生悬空 FK，与目标①冲突）。

## 目标②：LLM 生成域包 + 难度配额

- **ADR-0002 已修订**：否决范围收窄为"学生端运行时生成"；LLM 仅限教师端起草，学生演练仍是种子确定性纯函数。
- **域包资产化**（ADR-0008）：DomainPack 序列化为 JSON 存 Supabase；内置两包迁移为同格式数据（packId 不变、同种子字节级复现为硬约束），消灭代码态/数据态双轨。知识点顺序表（现硬编码于 question-picking.ts:6-14 的七类）搬入域包字段，各包自带清单与顺序。
- **生成流程**：教师描述场景（可附难度 SQL 样例）→ LLM 起草完整域包 JSON（库骨架 3-5 表 + 25-35 道模板 + 知识点清单 + 难度档位定义）→ 机器验证闸门 → 教师确认发布。
  - LLM：DeepSeek（deepseek-flash），服务端 route 调用，key 只存服务端 env，薄 provider 抽象（换模型不动业务代码）。
  - 交互：同步等待 + loading（Vercel `maxDuration=300` 容得下 1-3 分钟生成）；失败给重试入口，不静默。
- **机器验证闸门**（复用全量回归测试的断言口径）：
  1. 结构：类型合法、reference 指向的表/列存在、无循环依赖（可拓扑排序）、表数 3-5、模板数 25-35、难度 1-5、知识点取包内清单；
  2. 生成：固定测试种子生成会话成功、DDL 可在 sql.js 执行、参照完整性断言通过；
  3. 自判：每题参考答案可执行、结果非空、模板可实例化。
- **微调流程**：选中域包 → 输入修改意图（自然语言，可附 SQL 样例）→ LLM 输出修改后完整 JSON → 同一闸门 → 教师确认生效。与新建共用闸门，是调整域包的常规入口（比整包重新生成交互友好）。
- **版本化**（ADR-0009）：A 类改动（难度档位定义、演练配置——不参与种子生成）即时生效；B 类改动（库骨架、名称池、模板、数据规则）产生新版本，packId 带版本后缀（如 `student-course-grade@v2`），进行中会话钉旧版本直到换一套或重进，云端进度按旧键自动隔离（进度表主键 `(user_id, seed, pack_id)` 零迁移）。packId 基础名永不改。
- **难度与配额**：
  - 难度固定 1-5 五档（沿用现有 `QuestionTemplate.difficulty`，回归测试已有 1-5 校验）；域包为每档挂"名称 + 描述 + 代表 SQL 样例"定义。
  - 演练配置每域包一套：每次会话总题数 + 各难度档位数量分布；学生无限次开练，每次按当前配置生成。
  - 现状：difficulty 字段存在但抽题完全不消费（question-picking.ts 固定 10 题按知识点配额）——本目标让难度第一次真正参与抽题。

## spec 阶段待定细节（不阻塞共识，设计时定）

1. 抽题算法：难度档位分布与知识点配额（现为每知识点保底 1 题）如何共存、冲突时谁让步。
2. 域包管理页信息架构：生成表单、微调入口、放出清单、版本历史四块的布局。
3. DeepSeek 具体模型 ID 与 JSON 输出约束方式（response format / schema），实施时对照官方文档定。
4. 云端域包异步加载与现有同步 registry 的合并策略（内置同步 + 云端异步合并，首屏不闪错）。
5. 内置两包迁移的验收：同种子字节级复现如何断言（对比迁移前后生成的完整会话快照）。

## 关键事实备忘（探索结论，设计时引用）

- 进度粒度：`practice_progress` 主键 `(user_id, seed, pack_id)`，progress JSONB 内题目以 0 起题号索引关联（非 templateId），无版本字段——B 类微调无版本机制会静默错位（故有 ADR-0009）。
- 会话持久化：localStorage `sql-playground:seed` / `sql-playground:pack` 两键；换种子保留域包、换域包保留种子。
- 加载链路：`domainPackRegistry` 是模块级同步常量 + YAML 静态 import（turbopack raw loader），异步化需改造加载层。
- 外键现状：数据层引用池机制天然不出孤儿值（两包引用的都是 serialKey 列），真正缺口是 DDL 不声明 PK/FK、NULL 可能混入引用池、无拓扑排序、空引用池行为未定义。
